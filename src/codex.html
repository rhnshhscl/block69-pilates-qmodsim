Block 69 Pilates: proposal-to-module mapping

Block 69 Cafe runs reformer classes with four beds per session and releases next week's schedule every Sunday at 8:00 PM. The booking system has to survive a weekly flash crowd, bots that snipe or hold beds, guessable booking references, and a payment webhook that can fail. Each stressor maps to one QMODSIM module below. Every number in SCENARIOS and LAB comes from the pure functions in src/engines/qmodsim.js.

Mod 1 · 3 · Stochastic processes & arrival rates

Non-homogeneous Poisson flash crowd

Time t is measured in minutes from the 8:00 PM release. Background refreshes arrive at λ_base; the release adds a Gaussian surge of height A centred at t_peak with spread σ.

λ(t) = λ_base + A · exp(−(t − t_peak)² / (2σ²)) Λ(T₀, T₁) = ∫ λ(t) dt = λ_base · (T₁ − T₀) + A · σ · √(π/2) · [erf((T₁ − t_peak)/(σ√2)) − erf((T₀ − t_peak)/(σ√2))] P(N(T₀,T₁) = k) = Λᵏ · e^(−Λ) / k! f(t) = λ · e^(−λt) (inter-arrival density at a constant rate λ)
  1. Substitute u = (t − t_peak)/(σ√2), so dt = σ√2 du, and the Gaussian term integrates to A · σ√2 · (√π / 2) · [erf(u)], which equals A · σ · √(π/2) · [erf(u)].
  2. Arrivals are generated by Lewis–Shedler thinning: propose candidates from a homogeneous process at λ_max = λ_base + A, and accept each one with probability λ(t)/λ_max.
  3. When t_peak sits well inside the window, about 68.3% of the surge falls within t_peak ± σ, since erf(1/√2) ≈ 0.683.

Mod 6 · Queueing theory

M/M/c/K checkout-lock queue

A booking attempt that reaches checkout takes a bed lock. c = 4 locks are processed in parallel (one per reformer bed), lock hold times are exponential with mean 1/μ, and at most K sessions can hold or wait for a lock. Arrival number K + 1 is turned away.

a = λ / μ ρ = λ / (c · μ) Pₙ = P₀ · aⁿ / n! for 0 ≤ n < c Pₙ = P₀ · aⁿ / (c! · cⁿ⁻ᶜ) for c ≤ n ≤ K P₀ = [ Σₙ₌₀ᶜ⁻¹ aⁿ/n! + Σₙ₌ᶜᴷ aⁿ/(c! · cⁿ⁻ᶜ) ]⁻¹ P_drop = P_K = P₀ · cᶜ · ρᴷ / c! L = Σ n · Pₙ L_q = Σₙ₌ᶜ₊₁ᴷ (n − c) · Pₙ λ_eff = λ · (1 − P_K) W_q = L_q / λ_eff W = W_q + 1/μ Little's Law: L = λ_eff · W
  1. Birth–death balance gives Pₙ₊₁ · min(n + 1, c) · μ = Pₙ · λ. Chaining these yields the product form above.
  2. The engine works with log-terms ln Pₙ and subtracts the maximum before exponentiating, so K up to 200 and ρ ≫ 1 never overflow.
  3. W is built from L_q and 1/μ, not from L. The check L = λ_eff · W then holds only if busy servers equal λ_eff/μ (flow conservation), so it is a real test and not true by definition.
  4. For time-varying λ(t) in Scenario 1, P_drop(t) uses the pointwise stationary approximation: the steady-state formula is evaluated at each λ(t). Turned-away attempts = ∫ λ(t) · P_K(t) dt.

Mod 5 · Markov chains

6-state absorbing reservation chain

States: S0 Selecting, S1 Bed Locked, S2 Paid / Confirmed (transient); S3 Attended, S4 Expired, S5 No-Show (absorbing). Each transient row's self-loop is 1 minus its exits. If the exits add up to more than 1, they are rescaled to sum to 1.

P = [ Q R ] Q: 3 × 3 transient → transient [ 0 I ] R: 3 × 3 transient → absorbing N = (I − Q)⁻¹ expected visits to each transient state B = N · R absorption probabilities (rows sum to 1) t = N · 1 expected steps before absorption Conversion(attended) = B[S0, S3] Conversion(expired) = B[S0, S4]
  1. N = I + Q + Q² + … converges because every transient state reaches an absorbing state, so Qᵏ → 0.
  2. The engine inverts I − Q by Gauss–Jordan elimination with partial pivoting and checks N · (I − Q) = I in the V&V drawer.
  3. LAB compares B[S0, ·] against a token simulation of the same chain.

Mod 7 · Game theory in network defence

Anti-scalping normal-form game

The defender (studio) chooses D1 Rate Limit + CAPTCHA or D2 Deposit + SMS OTP. The attacker (scalper) chooses A1 Sniping or A2 Lock & Abandon DoS. All payoffs are in pesos per slot drop.

U_A(D1,A1) = (1 − r)·G − c_cap U_D(D1,A1) = −(1 − r)·g − f₁ U_A(D1,A2) = (1 − 0.4r)·H − c_cap U_D(D1,A2) = −(1 − 0.4r)·p_bed − f₁ U_A(D2,A1) = G − c_otp U_D(D2,A1) = −g − f₂ U_A(D2,A2) = H − F − c_otp U_D(D2,A2) = 0.5·F − f₂ p* = (U_A(D2,A2) − U_A(D2,A1)) / (U_A(D1,A1) − U_A(D2,A1) − U_A(D1,A2) + U_A(D2,A2)) q* = (U_D(D2,A2) − U_D(D1,A2)) / (U_D(D1,A1) − U_D(D1,A2) − U_D(D2,A1) + U_D(D2,A2))
  1. p* is the probability of D1 that makes the attacker indifferent between A1 and A2. q* is the probability of A1 that makes the defender indifferent.
  2. Baseline: CAPTCHA pushes attackers to DoS, a deposit pushes them back to sniping, and against sniping the studio prefers rate limiting. The best responses cycle, so the only equilibrium is mixed: p* ≈ 0.887, q* ≈ 0.713.
  3. The guide's inspection game is a special case. Set attacker gain G, fine F, audit cost C_audit, and let undetected cheating cost the defender G + F. The general solver then returns P(cheat) = C_audit/(G + F) and P(audit) = G/(G + F), which are the guide's p* and q*. A unit test checks this reduction.
  4. LAB also plays fictitious play: each side best-responds to the other's empirical frequency. In 2 × 2 games the path converges to the equilibrium.
Mod 2 · 10 · Security modelling & information entropy

Booking-token entropy and keyspace

H(X) = −Σ P(xᵢ) · log₂ P(xᵢ) = log₂(|Σ|ᴸ) = L · log₂|Σ| (uniform symbols) S = |Σ|ᴸ T_crack = S / (2 · R) 4-digit numeric: H = 4 · log₂ 10 ≈ 13.29 bits, S = 10⁴ 12-char alphanumeric: H = 12 · log₂ 62 ≈ 71.45 bits, S ≈ 3.2 × 10²¹
  1. At R = 10 guesses/s, a 4-digit code falls in about 500 s on average (8.3 minutes). A 12-char token needs about 5 × 10¹² years.
  2. Tokens come from crypto.getRandomValues(), never Math.random(). Bytes ≥ 248 are rejected so each of the 62 symbols has probability exactly 1/62.
  3. LAB measures the entropy per character of 1,500 generated tokens and compares it with log₂ 62 ≈ 5.954 bits.

Mod 4 · Monte Carlo & FAIR

Annual loss from slot-drop abuse

TEF ~ Beta-PERT(a_min, m_likely, b_max), α = 1 + 4(m − a)/(b − a), β = 1 + 4(b − m)/(b − a) N | TEF ~ Poisson(TEF · V) LM_primary ~ Lognormal(median, σ), LM_secondary ~ Lognormal(median₂, σ₂) with probability P_sec Loss_Total = Σ (Loss_Primary + Loss_Secondary) ALE = E[N] · E[S], E[S] = median·e^(σ²/2) + P_sec · median₂·e^(σ₂²/2) ROSI = [(ALE_base − ALE_mitigated) − C_control] / C_control
  1. Each trial samples TEF, the event count N, and per-event losses. The histogram and P90/P99 use these raw trial losses.
  2. The ALE estimate uses conditional Monte Carlo (Rao–Blackwell): it averages E[Loss | N] = N · E[S] instead of the raw loss. This is unbiased and cuts the seed-to-seed spread caused by rare, large secondary losses. Without it, the guide's ±1.5% convergence test failed at 1.84% (logged in AI_USAGE.md).
  3. The Deposit + OTP control scales V by (1 − e). The cost of the control enters through ROSI.
